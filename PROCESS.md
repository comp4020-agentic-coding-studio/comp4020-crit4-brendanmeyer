# Process overview


## What I built

The harp uses 11 strings, tuned to a C-major pentatonic scale (a five-note musical scale). This ensures that any two strings played together will not clash, so the player does not need to be careful about which strings they hit. Input can be given through mouse drag, touch swipe, or keyboard, and each note is synthesised using the Web Audio API rather than played from pre-recorded samples. The view opens on a blank screen with an inviting flash to play a note, the first pluck triggers the camera to show a string, and give the player the opportunity to reveal the remaining ten strings. Additionally, the hint dot plays itself to demonstrate a strum before any input is given, so a first-time user knows what to do without needing instructions.

## The moments that mattered

1. **The mobile bug only showed up after a resize, never after a reload.**
   On time when testing with phone-sized viewport, only two or three strings were visible instead of all eleven. [`599a85c`](https://github.com/comp4020-agentic-coding-studio/comp4020-crit4-brendanmeyer/commit/599a85c).Reloading the page at the same size fixed it. So I wondered what caused it. It wasn't until I realised that I had already played the instrument on the full desktop version then changed to the phone viewport, that the issue arrised. That meant the bug was that it was not handling resizing correctly. Claude was instructed with the issue, and was able to solve it [`683fbed`](https://github.com/comp4020-agentic-coding-studio/comp4020-crit4-brendanmeyer/commit/683fbed). It shows that there are many bugs that are not easy to find unless a certain path is followed, and that lots of testing is needed.

2. **A vague symptom ("a red x, then nothing plays")** [`599a85c`](https://github.com/comp4020-agentic-coding-studio/comp4020-crit4-brendanmeyer/commit/599a85c) ended up pointing to a browser interaction issue rather than a problem with the harp logic itself. The "red x" looked like the browser's not-allowed cursor, and because it happened after clicking and holding in one place, the likely cause was the long-press context menu. That can interrupt the gesture without sending the pointerup or pointercancel the harp expects, leaving the pointer state stuck. Before changing anything, Claude fixed it by preventing the contextmenu event and disabling text selection and the iOS touch callout on the harp surface ([`0574fcf`](https://github.com/comp4020-agentic-coding-studio/comp4020-crit4-brendanmeyer/commit/0574fcf)).
